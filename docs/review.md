# 复盘与优化(2026-10)

对三批设计稿落地后的整体复盘,从功能设计、模块划分、名称术语、内容体验四个维度做了只读评审,共约 100 条发现。本文件汇总结论、统一规范,并标明每条的处理状态:

- ✅ 本轮已处理　⏳ 后续演进(风险或改动面大,需要排期)　❓ 需要业务确认口径后才能改

## 一、总体判断

做得扎实的部分:
- A8 十步状态机、召集人守卫、行锁防并发、驳回回退、更正与撤回主干正确。
- 「无权数据不渲染」由后端裁剪(机构取会话机构、县区按本县区查询、省级无机构级字段、B7 库内无就医地机构)。
- 对标三档审批、小样本抑制、C3 席位有效期由服务端校验。

主要问题集中在四类:
1. **闭环只闭在自己的表里**:导出只有申请没有审批与下载;发布门禁只在 A8 内成立;A7 提交不产生下游任务;指标上线后机构侧看不到。
2. **“看起来能用”的假功能**:A12 编辑、A13 策略编辑、B6 只读查看器、A9 超时升级、A2 下钻等。
3. **面向开发的名字泄露到界面**:页面编号、区标签、技术词;同一概念多种叫法。
4. **按开发小组分的工程痕迹**:包、迁移、表前缀、前端 api 文件按小组切;无服务端单测与 CI。

### 2.3 文案规范

- 用户可见文案统一全角标点(，；：。);名称与字段用「」,口语强调用“”。后续在 lint 中加规则。
- 金额写「X 万元 / X 亿元」,不省略「元」;时限写「N 天」或「N 个工作日」;数字与中文单位之间加一个空格。
- 空状态:「暂无{对象}」;搜索无结果:「未找到符合条件的{对象}」;加载失败:「{对象}加载失败，请重试」并给重试按钮。
- 结果类提示:「已{动作}{对象}」,补充说明用逗号接在后面,不用「 · 」。
- 不向用户暴露技术词(服务端、分析引擎、接口)与内部流程(「同步至医保局发布工作流」);不承诺不存在的入口。

## 四、后续建议顺序

1. 先补工程底座:迁移集成测试(Testcontainers)、最小 CI(`mvn verify`、`pytest`、`npm run typecheck`)、状态常量与 check 约束。
