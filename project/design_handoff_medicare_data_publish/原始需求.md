# 角色与任务
你是资深 B 端产品设计师,熟悉政务系统、医保支付方式改革(DRG/DIP)和数据产品。请为“医保数据公开定向发布平台”设计一套可点击的高保真系统原型。

# 产品背景
- 依据国家医保局医保办函〔2025〕5号:统筹地区医保局通过“医保数据工作组”,按月/季/年向辖区定点医疗机构定向发布医保数据。
- 平台建在省级医保数据专区和“三医”协同平台之上,部署在医保专网/政务云。数据仅限内部工作使用,严禁外传。
- 产品主线是五个环节的闭环:多源归集 → 指标配置 → 智能推荐 → 审批发布 → 全息展示。
- 平台内分两个区:
  - 分析监测区:医保局内部使用,可到病例级。
  - 发布区:面向机构,只有经审批的聚合结果。
  - 数据从前者进入后者必须经过发布工作流。
- 内容按“钱、效、错”组织,并按主题域打包:DRG月度运行、病组结构、病种专题、机构专题、质量与监管、异地就医、县域医共体、床日付费、中医优势病种。

# 用户角色
1. 召集人(市医保局分管领导):看全息图、审批发布
2. 行政管理组(市医保局、经办中心):归集监控、指标配置、采纳推荐、生成报告、排程发布
3. 县区医保部门:本县区具名数据,其他县区只看汇总
4. 专家组成员(医院代表、高校专家):提指标建议、在线审阅专题报告
5. 委托分析团队(高校、研究机构):在受控环境做专题分析,只能导出经审核的聚合结果
6. 定点医疗机构(院领导、医保办、临床科室):看本院数据、对标、病组专题、预警,提交意见
7. 省级医保部门、其他统筹区:只看汇总层
8. 外部监督(人大代表、政协委员):限时只读

# 三条贯穿全局的规则(每个相关页面都要体现)
1. 对标三档:每个指标可配置为“匿名分位”(默认)、“匿名编号”(如“三级医院A”)、“具名PK与排行”。切换档位需审批。
2. 区域内外差异化:展示粒度由“谁在看 × 数据归谁”决定。
   - 区域内用户看区域内数据:最细,可到病组和诊疗行为。
   - 区域内用户看区域外数据(异地就医):按地区、等级、病种汇总;就医地机构排名仅医保局可见。
   - 区域外用户看区域内数据:只有汇总和经授权的对标值。
   - 区域外用户看区域外数据:不提供。
3. 仅内部标记:个人级、病例级指标标记为“仅内部”,界面上置灰且无法加入发布包。
